# 公众号回复草稿与后台配置说明

状态：开发交付草稿，尚未在公众号生效。仅能看到公众号已登录首页，未取得完整菜单及权限核验结果、类型/认证状态、实际菜单权限、小程序关联或服务器接管状态，不能宣称已完成线上配置。本轮不覆盖原有菜单、回复或素材。

## 交付文件怎么用

`content/wechat-content.json` 是关注回复、未匹配回复和关键词规则的单一文案源。`content/platform-links.json` 统一维护目标网页，由 `lib/wechat.ts` 读取。`{{bodyGuide}}` 等是统一链接配置的占位符，`{{platformPhone}}` 从平台机构电话读取；模板本身不能直接粘贴上线。运行 `pnpm prepare:wechat` 生成带真实完整地址的预览与文本，发布前应核对地址对应本次网站正式产物。

输出位于 `docs/wechat/generated/`：`menu.json` 和 `menu-table.md` 为菜单草稿；`replies.txt` 为可复制全文；`keyword-rules.json` 为规则清单；`first-use-article.md` 为完整地址版首次使用图文；`links.json` 为链接对照。`/wechat-preview.html` 提供网页审阅，不索引、不代表线上公众号配置。

文案中的【导览】等仅为关键词提示，不是按钮。全文回复采用可读文字和完整地址，不依赖未确认的富文本、网页授权或客服会话能力。微信后台若有实际可用的链接形式，应先预览真实账号效果；若链接不被当前能力支持，采用文末无链接版本，并在菜单已上线后使用菜单指引。

## 关键词规则表

全部规则采用 **完整匹配**：每个关键词分别录入同一条规则，不把多个词用顿号或逗号合成一个关键词。不启用包含匹配，不依据自由健康描述自动判断意图。规则没有重叠词；费用与合作严格分开。

| --- | --- | --- | --- |
| 人体导览 | 导览、人体 | `bodyGuide` | 解释部位查询和当前无审核对应资料的空结果 |
| 查找医馆 | 医馆、找医馆 | `clinics` | 名称、地址、地区查询；原记录不等于已授权合作案例 |
| 联系预约 | 预约、挂号 | `appointment` | 先选择医馆；关键词、点击和咨询不等于预约成功 |

| 活动状态 | 活动、福利 | 无链接 | 目前暂无已核实有效活动，不沿用历史夜市福利 |
| 本馆专属页 | 汇医堂中医诊所 | `clinic:huiyitang-guangzhou` | 只认完整名称 |

`fallback` 是给管理员看的未配置处理办法，不是公众号原生后台自动执行的“故障分支”，不得直接粘贴进用户回复。`linkKey` 用于统一生成链接，也不代表存在服务器路由或在线处理系统。

## 配置前先核对账号

由账号负责人在真实后台确认并记录：公众号类型、认证状态、自定义菜单与跳网页权限、自动回复可用能力、是否关联小程序、原有菜单和图文素材、是否启用服务器配置，以及是否由第三方平台接管消息。不要提交 AppSecret、Token 或 EncodingAESKey 到代码仓库或前端。

若启用了服务器或第三方消息接管，应先核实哪些消息由谁回复。不能同时启用重复处理后再以试发的方式碰运气；先在测试流程内确定关注事件、普通消息、未匹配消息和人工客服由一个明确渠道处理。本项目没有新增服务器接管程序。

平台机构电话沿用原网站记录，尚未独立回访；接待时间待确认。缺少真实接待系统时只能提供电话及使用说明，不承诺即时在线、专人回电或已转接。

## 原生后台配置步骤

以下是面向后台能力的操作清单；具体入口名称、可用字数和匹配选项以本账号当前后台为准。若未显示完整匹配或对应回复能力，保留草稿，不改用含义不同的设置冒充已完成。

1. 保留现状：记录现有菜单、被关注回复、收到消息回复、关键词规则、是否随机/多条回复、服务器或第三方设置。保存可恢复副本，并核对哪些设置当前正在生效。
2. 在本地审阅生成文本：每条链接需完整、没有 `{{…}}` 占位符；本馆链接包含正确 ID，合作电话号码从统一配置生成；费用规则没有合作价。网页未正式部署时，预览稿仅供内部审阅。
3. 在自动回复功能中配置被关注回复，使用生成的 `welcome` 文本。不要为了测试而批量取消关注；先使用后台预览或获授权的测试账号。
4. 建立 13 条关键词规则，每条选择完整匹配，分别录入表中关键词，设置一条完整文字回复。不要拆成多条随机回复，避免用户只收到一半入口或说明。核对后台保存后的字数与链接显示，不能依赖被截断的内容。
5. 在收到消息回复中使用生成的 `unmatched` 文本，并核对它与关键词规则、第三方回复及人工接待的实际衔接。不得保证某种消息优先级，实际行为须在账号里验证。
6. 按独立菜单清单配置网页跳转草稿。当前无有效活动和审核科普，不开放对应菜单；医生页面允许展示真实待确认状态，不能补造排班。
7. 使用后台可用预览检查全部文字与目标，再按下表真实验证。**只有取得本次发布授权，才发布菜单或覆盖线上回复。** 本次请求仅准备可审阅草稿，没有授权替换线上配置。
8. 发布后记录实际生效版本和时间。菜单、回复、图文及网页不会仅因源文件变更自动同步，后续修改必须重新生成并逐项配置验证。

## 验证用例

| 发送或操作 | 应看到的行为 |
| --- | --- |
| 导览 / 人体 | 人体入口与文字查询说明；不会生成诊断或推荐某馆 |
| 医馆 / 找医馆 | 可按名称、地址和地区查询的目录 |
| 预约 / 挂号 | 先选医馆；不会回复预约成功 |
| 地址 / 位置 / 导航 | 位置列表；岭海的歧义地址不直接导航 |
| 医生 / 出诊 / 时间 | 医生与排班待确认状态；不显示假医生或过期排班 |
| 价格 / 收费 / 费用 | 指定医馆费用核实指引；没有平台合作报价 |
| 合作 / 入驻 / 加盟 | 平台合作范围、99元/月或1000元/年、原网站机构电话及待核实说明 |
| 客服 / 人工 / 帮助 | 实际帮助渠道与接待时间待确认；没有已转接声明 |
| 活动 / 福利 | 暂无有效公开活动，不发送夜市旧价或空活动链接 |
| 四个医馆完整名称分别发送 | 每条只进入对应医馆页面，核对电话、地址、预约入口一致 |
| 发送“汇医堂”“汇医”“医生预约”“价格合作”或普通描述 | 不自动猜测医馆、诊断或合作意图；未匹配时引导完整关键词和帮助 |
| 从欢迎、关键词、菜单分别打开同一网页 | 内容相同、来源标识区分；分享来源不改变 canonical |
| 返回、刷新、复制链接，在微信外打开 | 真实静态网页可直开；无法拉起小程序时保留二维码与本馆电话说明 |

后台匹配、关注事件、链接点击和人工衔接只能通过真实账号证明，网页静态预览或脚本检查不能作为已配置生效证据。二维码解码验证也不等于小程序实际可用或预约履约成功。

## 无链接能力时的精简备选

仅当后台无法使用可打开链接、而菜单和对应关键词已实际配置成功时使用。不要在菜单尚未上线的阶段向用户承诺点击菜单可用。

**被关注回复备选：**

```text
欢迎关注汇医盟🌿

在广州查医馆、看地址、了解预约方式。

回复【导览】体验人体导览；
回复【医馆】查找医馆；
回复【预约】先选医馆，再看本馆渠道；
回复【合作】了解医馆平台合作。

也可点击已开放的底部菜单使用。
【】内是关键词提示，不是按钮。
出诊、费用与预约安排以医馆确认为准。
```

**收到消息回复备选：**

```text
您好，这里是汇医盟服务助手。
请单独回复【导览】【医馆】【预约】【合作】获取入口。
需要其他帮助，请回复【帮助】，或查看已开放菜单中的联系客服。
具体健康问题请联系接诊医师。此条是自动指引，不代表已转接人工。
```

关键词回复若链接不受支持，按已经实际开放的菜单名称改为清晰路径指引；菜单也未开放时先保持内部草稿。暂缺入口不能通过返回虚构链接或“配置成功”文字解决。
