# 公众号交付物回归检查

执行位置：项目根目录。`scripts/check-wechat.mjs` 只读取源文件、生成稿和可选静态产物，不发布菜单、不发送消息、不上传 COS。

```bash
pnpm prepare:wechat
node scripts/check-wechat.mjs --source-only
pnpm build
node scripts/check-wechat.mjs
```

`--source-only` 也会核对每个目标实际存在源码路由，只跳过 `dist/client` 静态 HTML 检查。完整模式必须在本轮最终构建后运行；缺少目标文件、目标其实是 404、医馆 canonical 含来源参数或配置预览允许索引都会失败。

检查范围：

- 三组十个菜单及各自真实页面绑定；仅使用网页 `view` 动作，不混入未配置 AppID 或服务端事件。
- 十四个完整匹配规则、四十个无冲突关键词，逐一保留原后台二十一个关键词并检查各自去向；营业时间独立规则只引导本馆核实，不等同医生出诊。四家医馆仅使用统一资料里的完整名称，各自链接绑定正确的医馆 ID、页面和平台推广来源。
- 关注、未匹配、关键词及图文分别使用限定的来源标签；查询参数只能包含匿名入口字段，不夹带病情、人体选择或身份数据。
- 生成稿与统一链接、源文案同步，完整文本不缺失，没有遗留链接占位符；导出状态明确为未发布草稿。
- 患者费用规则不混入合作报价，也不跳合作页；无有效活动时没有活动链接；未审核科普和历史活动不占菜单。
- 所有链接均在配置的 HTTPS 域名内，有对应源码和正式静态路径。配置源中不包含 AppSecret、Token、EncodingAESKey 等秘密字段。

这是技术回归检查，不能证明公众号权限、规则真实生效、人工接待、小程序真机拉起、预约成功、实际电话接通或医馆展示授权。相关事项必须在账号和业务端分别验收。公开内容或账号能力变化后，需先完成真实资料核验，再审阅并更新相应检查约束，不能直接删掉失败断言。
