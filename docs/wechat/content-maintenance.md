# 公众号与网页内容维护规则

状态：2026-10-24 开发交付草稿。此文规定后续维护方式，不表示公众号栏目、人工客服、预约记录或统计服务已经接入。现阶段继续使用静态 COS 部署，公众号原生后台单独配置。

## 三个持续更新栏目

| 栏目 | 可以更新什么 | 当前可交付内容 | 发布条件 |
| --- | --- | --- | --- |
| 平台使用指南 | 人体导览、文字查询、医馆筛选、联系预约、地址导航、变更与反馈 | `first-use-article.md` 完整图文草稿及手机使用指南网页 | 操作与实际上线功能一致，链接和截图经手机核对，业务负责人确认后发布 |
| 医馆与出诊信息 | 医馆基础资料、营业时间、医生及分馆排班、临时停诊、确认价格、有效活动 | 四条原网站医馆记录；目前暂无核实医生和有效排班，不创建虚构更新 | 医馆确认并有展示授权，记录来源、核实人、有效期及对应医馆；缺失时显示待确认 |
| 中医知识内容 | 适合公众号发布的原创或有使用权文章/视频，标明来源、作者和相应审核信息 | 网站保留既有养生内容；现有资料缺少完整的作者、专业审核与发布权限记录，暂不纳入公众号科普菜单或新推荐 | 核对内容使用权、作者信息、专业审阅和账号发布资质；通过后才开放真实列表与详情 |

平台使用指南不混入医学诊断或疗效承诺。中医知识内容不直接拼接某家医馆的预约推广来凑转化。没有完成审核的知识内容，不用一句免责声明代替审核。

本轮首页不挂载旧的全量养生推荐组件。后续收到审核记录后，须先实现按获批文章 ID 筛选的推荐与菜单，再开放栏目；仅向 `approvedKnowledgeArticles` 填入一个值，不会自动启用旧文章全集，也不能作为完成审核的依据。

## 统一内容与链接来源

| 信息 | 唯一维护位置 | 更新后的必要动作 |
| --- | --- | --- |
| 医馆名称、电话、地址、图片、授权、服务、医生和价格 | `content/clinics-source.json`；`lib/clinics.ts` 负责读取与已核实内容筛选 | 核对本馆 ID；检查详情、目录、预约、导航、医生入口及专属分享；不另在回复文案中手写电话 |
| 公众号目标网页、来源标识、菜单映射 | `content/platform-links.json`；`lib/wechat.ts` 负责读取 | 重新生成菜单和回复产物，检查真实完整 URL；确认网页已部署后再配置公众号 |
| 关注回复、未匹配消息、关键词回复 | `content/wechat-content.json` | 保留 `{{…}}` 链接/电话占位符；生成后复制实际完整文本，不复制模板占位符 |
| 首次使用图文 | `docs/wechat/first-use-article.md` | 按统一链接配置输出完整地址版本，更新实际页面截图与发布审核记录 |
| 平台机构电话 | `content/platform-links.json` 的 `platformPhone`（由 `lib/clinics.ts` 导出） | 新号码先由业务方确认用途，接待时间单独核实；同步生成合作、帮助和回复稿，不将其当某家医馆电话 |

当前医馆 `codeAuditedAt` 是代码整理日期，`businessVerifiedAt` 才是业务核实日期。二者不能混用。授权为 `unconfirmed` 的记录不得包装为已授权合作案例；来源为原网站也不等于已回访。

平台合作与客服电话由用户于2026-10-24明确确认，本轮使用统一配置中的 `platformPhone`；接待时间仍待确认，也没有已接入的在线人工客服。此项确认仅适用于平台电话，不自动确认各医馆电话、排班或展示授权。原后台只读备份中的旧号码保持原样，不修改历史证据。

在项目根目录运行 `pnpm prepare:wechat`，由 `scripts/generate-wechat.mjs` 输出 `docs/wechat/generated/` 中的 `menu.json`、`menu-table.md`、`replies.txt`、`keyword-rules.json`、`first-use-article.md` 与 `links.json`。这些产物是审阅/配置草稿，不会自动发布公众号。网页预览为 `/wechat-preview.html`，设置不索引，不应作为患者菜单入口。

2026-10-24 依据当前后台可见配置，将原6条规则的21个关键词全部保留，整合为14条规则、40个唯一完整匹配词。原半匹配已在统一文案中改为完整匹配；是否实际生效以后台保存及消息验证为准。营业时间4词单独进入 `clinic-hours`，说明资料尚待本馆确认，不从营业时间推断医生出诊。后续新增或删除别名应同时更新统一文案、回归检查与后台规则，不能在后台独立维护第二套词表。

## 资料确认的最小记录

由实际负责人员补齐以下内容后再公开相应资料。模板只说明字段，不是新的医馆或排班数据。

| 类别 | 应保存的依据 | 页面显示或处理原则 |
| --- | --- | --- |
| 医馆与图片 | 医馆 ID、登记名称、执业资料、确认人/时间、展示范围与授权记录、图片权利来源 | 展示状态与证据一致，图片缺失时用空态，不生成冒充门店的替代照片 |
| 营业时间 | 门店 ID、适用日期、常规营业时段、节假日规则、临时调整、确认人 | 单独标为医馆营业时间，不据此生成医生在诊或有号状态 |
| 医生与排班 | 医生 ID、姓名、资质/执业核验、公开授权、医馆 ID、实际接诊地点、日期、时段、有效起止、停诊状态、来源、确认人/时间 | 医生跨馆时按医馆分列地点和时段；没有真实号源接口，不显示可立即预约或剩余号数 |
| 服务与人体映射 | 实际服务、对应医馆、专业来源、审核人/资质、审核日期、适用边界 | 未审核的部位对应关系只列为待确认；不能从点击推断病情或推荐疗效 |
| 诊疗价格 | 医馆 ID、项目、金额、计价单位、适用条件、排除项、有效期、本馆确认与授权 | 费用由对应医馆确认；候选转录或旧活动价不能当现行收费 |
| 预约方式 | 医馆 ID、电话/系统、小程序 AppID 与页面路径（如适用）、真实二维码、适用客户端、验证时间 | 本馆绑定；二维码目标必须实测；只有预约系统明确确认后才描述为预约成功 |

当前统一结构尚未提供完整的排班有效期和临时停诊字段，而且没有已核实医生记录。新增排班前，需同时补齐有效期结构、过期和停诊处理、页面展示及验证；不能只写入一段文字后长期显示为有效。医生独立页在真实资料与授权齐备后再建立。

汇医堂涉及代煎的服务介绍，按业务方本次说明使用 **“免费代煎，不送药”**。这条来源只适用于汇医堂，不应自动复制到其他医馆。适用项目、范围与有效期仍由该馆确认后记录；没有已确认收费项目时，不把“免费代煎”扩写为其他项目免费。

## 活动发布与到期规则

当前没有已核实、在有效期内的公开活动，公众号“最新活动”菜单不启用，“活动/福利”关键词明确回复暂无公开活动。历史夜市信息不自动延续价格、福利或日期。

活动记录应至少包括：唯一 ID、举办方、开始与结束时间（含时区）、具体地点、参与方式、真实价格、适用条件与数量限制（如有）、取消/变更规则、咨询渠道、资料来源、确认人及公开授权。活动列表和详情只有资料齐备时才可启用。

静态网站不会因为自然时间经过就自动重新构建。若后续上线活动或排班，运营须在发布时明确到期责任人，并在截止前更新数据、重建上传和检查缓存；有条件时再接真实服务处理到期。无法保障到期维护时不发布“当前有效”入口。到期后移出有效列表，详情保留“已结束”及实际日期；菜单和自动回复同步撤下优惠，不继续引导报名。

## 内容审核与发布记录

每次更新应留下版本、编辑人、内容类型、来源、专业审核人及审核范围、业务批准人、有效期、网页构建版本、公众号稿件或规则位置、实际发布时间和回退位置。专业审核重点是医生、排班、服务对应、价格适用说明、科普和医馆推广内容，不能仅审核页面排版。

2026-10-24 当前后台主体显示“广州汇医盟健康科技有限公司（企业）”，认证页有效期至2027-09-10；类型字段只显示“公众号”，具体分类仍待核实。服务器/第三方接管状态因开发管理迁移至另需登录的平台而未核验。涉及医疗科普或医馆推广的具体发布要求，由负责人结合账号后台实际资质核对；技术人员不能把微信认证或菜单权限推断为具备相应医疗内容发布资质。

## 一次更新的操作顺序

1. 先收集并核实资料、授权与有效期，再修改统一数据或回复源文件；避免先改公众号文本而网页仍是旧版本。
2. 在本地生成预览，核对本馆 ID、电话、地址、预约目标、完整链接和来源参数，运行项目要求的检查。
3. 完成专业与业务审核。网站维护者按 COS 流程备份并部署，手机直接打开正式地址复核。
4. 公众号管理员保留当前菜单、回复和素材副本，配置草稿、预览验证；取得本次发布授权后再发布。原配置的删除或覆盖不属于“生成草稿”。
5. 用真实公众号逐个测试欢迎消息、每组关键词、完整医馆名、未匹配消息与返回操作；记录账号、设备、时间与结果。自动回复和人工接待衔接未验证前，不提示已转接。
6. 资料更正或到期时同步修改网页、回复、图文和菜单，保留更正记录。已群发图文无法通过改源文件自动更新，应按后台实际可用方式更正并避免继续传播过期入口。

## 数据反馈的边界

当前没有配置可用统计服务、共享数据库或预约存储，月报相关数据使用“暂未统计”。来源参数只区分公众号菜单、欢迎回复、关键词回复、图文与医馆自有分享，不携带患者身份、病情或人体部位。

接入后也应分别报告：页面访问、电话点击、导航点击、预约入口点击、真实咨询、确认预约、实际到店。后一组需要真实处理系统或医馆记录；点击不能推算为咨询或到店。不得通过前端 localStorage 制作全站统计，也不得把收到的健康描述发送到普通营销统计服务。
