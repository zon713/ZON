# 公众号后台配置、验证与回滚

日期：2026-10-24（北京时间）。本文件供管理员在确认发布时执行。网页、链接配置与回复文案可以先审阅；本次没有替换线上菜单、回复、关联或服务器设置。

## 1. 先留存当前配置，再考虑保存或发布

登录正确的“汇医盟”公众号，核对账号主体。按实际界面寻找自定义菜单与自动回复入口：本轮可见新版侧栏称“互动管理”；旧版可能显示其他分组名称，可搜索功能名，不依赖旧截图里的固定点击位置。先完成下面的记录，不切换消息服务器、不撤销第三方授权，也不整组删除现有菜单：

1. 保存菜单树截图，逐个记录菜单名、动作类型、完整 URL、素材或小程序目标，以及当前发布状态。订单、券卡、权益、历史预约或售后入口须单独登记。
2. 复制当前关注回复、收到消息回复全文，保存当前开关与素材信息。
3. 逐条记录关键词规则：规则名、关键词、实际匹配方式、回复内容、素材或完整链接、是否随机回复等当前配置。
4. 记录当前关联小程序和第三方平台的名称、职责与维护联系人；记录消息服务器是否启用及由谁维护。只记录状态，不复制密钥。
5. 保存时间、操作者和待回滚的当前版本。敏感配置、登录凭证与用户私信不进入公开仓库或网页。

若后台没有完整导出功能，用截图加文本清单即可。历史提案与网页部署备份不替代这次留存。自动回复的“保存”也可能直接生效，不能把它当成一定无影响的后台草稿操作。

## 2. 核对权限与消息处理方式

当前账号类型、认证、跳网页能力、关联与接管均待核验，不能根据旧截图或已登录状态推定。逐项查看实际后台：

| 检查项 | 需要确认 | 本次处理 |
| --- | --- | --- |
| 账号类型与认证 | 当前类型、认证状态与有效期 | 记录实际结果，不由名称推断 |
| 自定义菜单 | 实际可选动作、跳网页是否可用、目标域名访问结果 | 有网页动作才采用网页方案；没有时保留当前有效入口，不擅自切换接入模式 |
| 自动回复 | 原生关注、关键词、收到消息回复是否可用；实际匹配选项 | 优先使用原生后台，不为静态链接回复另建后端 |
| 服务器配置 | 是否启用、当前处理方及职责 | 查看状态；不通过切换开关试验原生回复 |
| 第三方授权 | 是否管理菜单、回复或人工接待 | 联系实际维护者核对生效机制，不同时向多个系统写入 |
| 关联小程序 | 真实 AppID、路径、账号允许方式及真机目标 | 未核验不填占位 AppID、不推断二维码的页面路径 |
| 客服接待 | 真实渠道、人员、接待时间、消息处理衔接 | 不写“已转接人工”或实时在线，除非确有服务接通 |

如果服务器或第三方已接管消息，先由维护者解释当前规则的优先级与回复来源；不要为了启用本稿而停用现有服务。首次核对先使用非健康内容的测试关键词，避免把用户病情带入测试或普通统计。

## 3. 先部署并验证目标网页

本项目沿用静态 COS 部署。菜单 URL 必须使用发布包中的正式 HTTPS 地址及实际导出的 `.html` 路径，不能填本地地址、开发路由、演示站或未经部署的新页面。

1. 按网站发布说明构建并预览；确认新页面已包含在导出文件中。
2. 备份当前 COS 文件，再上传本次发布文件；保持旧页面及现有有效网址可访问。
3. 用正式域名逐一直接打开目标链接、刷新，并检查页面标题、返回、手机滚动、空态和对应医馆联系方式。
4. 使用微信真机打开同一链接，核对安卓与 iPhone 中的页面、拨号、地图和原预约二维码。小程序预约还须验证真实目标、所选医馆及实际系统确认方式。
5. 页面上线前，菜单表和回复中的新地址均标为“待部署”，不能当作已经可对用户使用。

来源参数仅标识固定入口，例如公众号菜单、欢迎回复、关键词回复或医馆分享。不要追加用户消息、姓名、电话、病情、人体部位或搜索词。来源标签不等于统计已采集；没有可用统计服务时仍写“暂未统计”。

| 找中医 | 人体导览 | 跳网页：人体导览与文字查询 |

“最新活动”和“中医科普”当前不占菜单位置；有真实有效活动或适合发布且完成审核的内容后，再评审增加。不能把旧夜市优惠当作当前活动。

菜单 JSON 是可审阅的数据草稿，没有向微信接口提交，不应直接拿它自动覆盖线上菜单。如果当前配置由原生后台维护，就在实际页面逐项填写与预览；不要默认调用菜单 API 与原生后台效果等同。保留已有有效服务；若旧入口需要调整位置，先确认迁移与回滚方案。

后台没有网页跳转动作时，停止配置这一动作，记录缺少的权限。若现有已验证的图文或服务入口可承接相同任务，可另行选择并验证；不以启用未知服务器、借用其他账号或填假小程序参数来补齐。

## 5. 配置关注、关键词与收到消息回复

使用 [完整回复文案](./generated/replies.txt) 和 [关键词配置草稿](./generated/keyword-rules.json)，并保留原回复。文案中的【导览】等是关键词提示，不是可点击按钮。[第一次使用汇医盟图文稿](./generated/first-use-article.md) 可作为公众号内容草稿审阅，不代表已上传图文素材或发布文章。

### 关注回复

先确认关键词规则和底部菜单实际可用，再启用提及这些入口的关注回复。优先用原生文本框粘贴可读文本和真实 HTTPS 地址；只有实际后台预览和微信真机都支持相应链接形式时，才采用该形式。不预设文本会自动变成链接，也不直接粘贴未经验证的 HTML。

如果菜单或关键词尚未配置，先保留原有有效欢迎语；不要对用户说新入口已经接通。关注回复全文交付为草稿，不因文件生成而自动生效。

### 关键词回复

1. 原生后台若提供“全匹配”或等价的精确匹配，优先使用，每个已审阅的同义词明确列入对应规则。若实际界面不同，先确认真实匹配语义再配置，不假设存在某个选项或固定长度限制。
2. 避免使用会包含大量无关消息的模糊匹配。配置前对照原规则，检查一个词是否重复出现、医馆简称是否歧义，不猜测后台冲突优先级。
3. “导览/人体”“医馆/找医馆”“预约/挂号”“地址/位置/导航”“医生/出诊/时间”“价格/收费/费用”“合作/入驻/加盟”“客服/人工/帮助”“活动/福利”分别使用对应回复。
4. 医馆完整名称或明确简称，只返回本馆详情页。歧义名称让用户选择，不自动指向某馆；没有得到确认的简称不要加入。
5. “价格/收费/费用”只引导查看指定医馆已确认的诊疗价格或联系该馆，不回复平台合作收费。“合作/入驻/加盟”解释平台合作，不表述为尚不存在的品牌加盟。
6. 预约回复先让用户选择医馆；收到关键词不代表已经创建预约。客服回复只给真实渠道，不冒充转接或接单。活动回复没有当前有效活动时，明确暂无公开活动。
7. 每条规则用手机发送精确词及相近但不应匹配的文本测试。若一条消息收到多条回复，先核查原规则和接管方，不能只根据网页预览判定成功。

文字 URL、菜单跳转或账号权限尚未可用时，不发布无效地址：保留原有可用回复，并把新规则标为“待配置”。一旦规则已启用，未命中情况用真实可用的菜单或帮助方式引导；不能把网站暂未部署的地址当兜底。

### 收到消息与人工衔接

先确认收到消息回复是否只对未匹配消息触发，以及与人工接待、服务器、第三方回复的实际关系。采用简短入口指引，不承诺响应时限。已有人工接待时，以接待方实际工作方式配置，避免同一消息重复自动回复。具体健康问题引导联系接诊医师，不自动诊断或生成用药方案。

## 6. 可选服务器接入条件

本次静态网页与原生后台文本回复不需要新增消息服务器。只有确认存在必须由服务器处理的消息、真实客服衔接、预约记录或统计需求时，再决定接入现有后端或建设后端。

接入前至少具备：账号相关权限、受控 HTTPS 服务地址、明确维护者、适用的微信官方当前文档、测试与回滚环境，以及所需的服务端存储和处理流程。没有这些条件时，将功能标为“待接入”，不在浏览器或 localStorage 中模拟全站记录。

服务端开发与验收需按当时官方文档核对：接入验证、请求验签、启用加密时的消息解密及响应加密、账号归属校验、消息与事件重复投递处理、响应与失败重试机制、处理日志及监控。本文没有实现或验证这些服务器能力，也不凭历史文档指定固定超时、消息窗口或接口权限。

AppSecret、Token、EncodingAESKey 等仅保存在受控服务端密钥配置中，不进入前端代码、网页包、普通日志、回复文案、截图或公开仓库。菜单 API、客服、预约与统计分别按真实接入范围验证，不把某个接口可调用扩展为整套业务已可用。

电话点击、导航点击、预约入口点击仅是操作事件。真实咨询、确认预约和实际到店需要各自业务依据；没有相应后端或医馆反馈时，保持“暂未统计”。人体部位与病情描述不默认发送给第三方统计。

## 7. 发布前核对与发布影响

获得发布授权后，由管理员确认当前账号、网站版本和保留的旧配置，再执行实际后台提供的保存或发布动作。菜单、关注回复、关键词、收到消息回复分项核对，逐项记录执行时间与结果；不假设“保存”一定只是草稿，也不推定固定生效延迟。

发布前用普通手机账号核对：

- 所有已配置菜单直接到正确网页；返回、刷新、筛选、无资料空态均正常。
- 四家现有医馆记录的电话、地址、导航和预约入口各自绑定；待确认地址不能误导航。
- 医生、排班与地点没有编造；营业时间和医生出诊分开；缺资料时有真实提示。
- 每个关键词、医馆名、歧义词、未匹配消息和关注触发符合预期，且无重复回复或虚假人工接通。
- 咨询诊疗价格不会收到 99 元/月合作费用；活动过期后不会继续发送优惠。
- URL 和页面分享码可直接打开或扫码；原预约码单独真机核对，不能与详情分享码混淆。
- 新老用户原有有效预约、订单、权益或售后入口仍可找到；存在这些服务时先安排保留位置。

发布会改变患者实际看到的入口与回复。新链接故障、目标医馆错误、人工衔接异常时，应立即恢复上一份已验证配置；不要用新增承诺掩盖故障。

## 8. 回滚与维护

1. 菜单错误：用发布前留存的菜单树与完整目标恢复，核对旧预约、订单及权益入口。
2. 回复错误：逐条恢复原规则与文案，检查重复关键词和接管方；不为回滚切换未知消息服务器或取消授权。
3. 网页错误：按 COS 备份回滚受影响页面与资源，再检查缓存和正式 URL；保留线上已存在的必要服务入口。
4. 记录影响时间、错误入口、恢复版本和真机复测结果，不保存无关患者消息或健康资料。
5. 以后改地址先修改 `content/platform-links.json`；回复内容在 `content/wechat-content.json` 维护，链接解析共用 `lib/wechat.ts`。运行 `pnpm prepare:wechat`（`scripts/generate-wechat.mjs`）再生成菜单和回复清单，完成预览、部署与核对；不要直接手改生成文件。后台不会因本地配置变化自动同步。
6. 排班、停诊、活动到期按真实有效时间维护；发布科普、具体医疗服务与医馆推广前分别补充来源、作者、审核人和适用账号要求。免责声明不能替代专业审核。

当前必须由业务方补充或核对：上述账号能力和现有配置、平台真实接待方式与时间、医馆资料与展示授权、医生与排班、收费与适用条件、汇医堂原版 Logo、原预约码真机目标，以及如需启用统计或消息后端时的服务与维护权限。不要提交密码、验证码或前端密钥来补充这些资料。
