## 单一来源与后续更新

| 修改对象 | 维护文件 | 同步动作 |
| --- | --- | --- |
| 医馆名称、电话、地址、图片、授权、医生、服务与价格 | `content/clinics-source.json`，由 `lib/clinics.ts` 读取 | 按本馆 ID 核对目录、详情、医生、预约、位置及分享入口 |
| 正式域名、网页路径、菜单、平台机构电话与账号待核验状态 | `content/platform-links.json` | 重新生成菜单、回复、图文与链接清单，再部署和人工核对后台 |
| 关注、关键词、未匹配回复 | `content/wechat-content.json` | 保留模板键，由生成脚本输出完整可复制文本 |
| 网页链接与来源参数解析 | `lib/site-links.ts`、`lib/wechat.ts` | 同时验证开发路由与 COS 的 `.html` 路径，避免多套手写地址 |
| 医馆网页分享码 | `scripts/generate-share-codes.mjs` 根据医馆与正式域名生成，记录在 `content/clinic-share-codes.json` | 重新生成 PNG 并独立解码核对本馆、来源与图片哈希；不改动汇医堂原小程序码 |
| 首次使用文章 | `docs/wechat/first-use-article.md` | 更新真实截图、说明及链接生成结果后再作为公众号素材审阅 |

在项目根目录运行 `pnpm prepare:wechat`，由 `scripts/generate-wechat.mjs` 生成 `docs/wechat/generated/` 内的文件；`pnpm check:wechat` 核对来源、规则及静态目标。运行 `pnpm prepare:share-codes` 生成网页分享码，`pnpm check:share-codes` 检查现有 PNG 的独立解码结果与清单。不要直接修改生成产物来维护地址。生成脚本不登录微信、不提交菜单、不修改回复。

分享码使用固定开发依赖 `qrcode` 生成，`pngjs` 读取实际 PNG，独立的 `jsQR` 解码。四家分别对应自身详情页面，编码的是 `clinic=本馆ID&source=clinic&entry=clinic_share`，不包含健康信息。公众号与平台分享分别使用各自固定来源标签，不继承用户查询文字。

原生回复的建议是精确匹配；后台实际若提供“全匹配”或等价选项才采用，并逐词测试。括号文字是提示，不是按钮。`fallback` 是管理员未配置时的处理说明，不是自动故障转接程序；网页预览中的命中也不代表真实公众号已收到消息或接通人工。

## 最小发布顺序与影响

1. **完成资料及账号核对。** 管理员先保存当前菜单树、完整目标、关注/关键词/收到消息回复和接管状态。保留原有有效预约、订单、权益或售后入口；不切换服务器开关，不撤销第三方授权。
2. **构建本次版本。** 运行 `pnpm prepare:wechat`、`pnpm prepare:share-codes`、`pnpm typecheck`、`pnpm check:wechat`、`pnpm check:share-codes` 及项目现有检查与构建命令，使用实际结果记录本次状态。不要把上轮“28 页构建”等旧记录直接当作本轮验证。
3. **备份 COS 后上传网页。** 按既有部署配置处理，先静态资源，再非首页页面，最后更新 `index.html`。维持旧有效网址和 SEO。需要刷新缓存时按现有服务操作，保留可回滚文件。
4. **先验收正式网页，再配置菜单。** 正式域名逐一直接打开和刷新新 `/locations.html`、`/service-guide.html`、`/support.html`、`/privacy.html`；审阅页 `/wechat-preview.html` 只供审阅并保持不索引。另验首页、人体导览、医馆详情和原预约入口。确认新目标已部署前，不发布指向它们的公众号菜单或回复。
5. **经发布授权后逐项应用公众号配置。** 从生成清单复制完整地址和文本，按本账号实际支持的原生操作配置。菜单 JSON 仅供审阅，不自动调用 API 覆盖线上配置；保存回复也可能立即生效。先核对原配置和预览，再由管理员执行实际保存/发布动作，记录影响时间。
6. **用普通手机账号验证真实触发。** 新关注测试确认欢迎语；逐个菜单、全部关键词、完整医馆名、歧义名称与未匹配消息确认去向和无重复回复。测试诊疗价格不会收到合作价；客服不会声称已转人工；无医生排班、活动、地址不明与无部位对应资料时均有真实提示。线上预约与拨号仅在约定测试范围内验证，不生成无必要的真实订单。
7. **发布后检查与回滚。** 核对死链、跳错本馆、微信识别、异常反馈及原服务入口。错误时恢复留存的菜单/回复；网页按 COS 备份恢复并复测。不能通过删除历史订单、切换未知消息服务或取消授权来回滚。

具体后台步骤、不能取得某项权限时的处理及回滚方法见 [后台配置说明](./backend-setup.md)。手机号、导航、小程序、公众号回复与真实履约分别验收，网页截图通过不能代替这些结果。
